# VOID bootstrap / DNS-Seed узел

Версия 0.2 — добавлен **веб‑интерфейс** управления и **зашифрованный протокол обмена
списками seed‑нод** (`VOID-SEED/v1`). Узел одновременно работает как:

1. **libp2p bootstrap/relay** (`/void/v1` + `/void/kad/1.0.0`) — ровно то же, что и раньше, порты TCP/UDP **4001** по умолчанию.
2. **DNS‑Seed сервер** — отдельный TCP‑порт **4010**, выдаёт клиентам и другим seed‑узлам зашифрованный список известных VOID‑нод.
3. **Панель управления** — HTTP на `127.0.0.1:8080` (только локально).

Ничего открыто по сети не передаётся: весь seed‑обмен проходит внутри AEAD‑шифрования
с двусторонней Ed25519‑аутентификацией и Perfect Forward Secrecy.

---

## Требования

- [Rust](https://rustup.rs/) (stable)
- Публичный IP (или DNS) + проброс на роутере:
  - **TCP 4001** и **UDP 4001** — для libp2p,
  - **TCP 4010** — для seed‑обмена между узлами.
- Порт веб‑интерфейса (`8080`) **не** нужно пробрасывать — он слушает только localhost.

При первом запуске появится файл `bootstrap_peer.key` — **берегите его**, он определяет

`known_nodes.json` со списком изученных seed‑нод.

## Веб‑интерфейс

Откройте в браузере:

```
http://127.0.0.1:8080
```

Что можно делать:

- видеть свой PeerId, порты, uptime и готовую `multiaddr`‑строку для `void-bootstrap.txt`;
- указать свой публичный IP/домен (он будет анонсироваться другим seed‑нодам при обмене);
- вбить `IP` или `IP:port` другого узла VOID / DNS‑Seed — узел выполнит зашифрованный
  handshake, проверит, что удалённая сторона действительно принадлежит сети VOID,
  и обменяется списками;
- смотреть список известных нод, удалять устаревшие;
- читать журнал последних событий.

### Переменные окружения

| Переменная   | По умолчанию        | Описание                                       |
|--------------|---------------------|------------------------------------------------|
| `LISTEN_PORT`| `4001`              | Порт libp2p (TCP + UDP/QUIC).                  |
| `SEED_PORT`  | `4010`              | Порт зашифрованного seed‑протокола.            |
| `SEED_BIND`  | `0.0.0.0:$SEED_PORT`| Адрес биндинга seed‑сервера.                   |
| `WEB_BIND`   | `127.0.0.1:8080`    | Адрес биндинга веб‑UI. **Держите на localhost** — там нет авторизации.|
| `RUST_LOG`   | `info`              | Уровень логов tracing.                         |

## Протокол `/void-seed/v1` — как работает обмен

```
    Клиент (нода A)                                Сервер (нода B)
        |                                               |
        |  msg1 = e_c_pub (32 случайных байта)          |
        | --------------------------------------------> |
        |                                               |
        |  msg2 = e_s_pub || AEAD(k1, n=0, auth_s)      |
        | <-------------------------------------------- |
        |                                               |
        |  msg3 = AEAD(k2, n=0, auth_c || request)      |
        | --------------------------------------------> |
        |                                               |
        |  msg4 = AEAD(k2, n=1, response)               |
        | <-------------------------------------------- |
```

- **Обмен ключами**: эфемерные X25519 ключи (DH даёт общий секрет).
- **Вывод ключей**: `HKDF‑SHA‑512` с `salt = "VOID-SEED/v1" || e_c || e_s` →
  64 байта, из которых первые 32 — `k1`, вторые 32 — `k2`. Все последующие
  сообщения шифруются `ChaCha20‑Poly1305` (AEAD, 96‑битный nonce = счётчик).
- **Аутентификация**: статический `Ed25519` ключ каждой стороны (тот же,
  что и у libp2p `PeerId`) подписывает `"VOID-SEED/v1|<direction>|e_c||e_s"`.
  Внутри шифрованной части также передаётся PeerId и `protocol_version = "/void/v1"`.
  Узел **без** корректной подписи и ключа VOID не сможет ни расшифровать
  `msg2` (нет сессионного ключа), ни подделать `msg3`.
- **Perfect Forward Secrecy**: эфемерные ключи уничтожаются после сессии.
  Даже если статический ключ `bootstrap_peer.key` потом утечёт — прошлый трафик
  расшифровать уже нельзя.
- **Что видит пассивный наблюдатель**: 32 «случайных» байта, далее зашифрованный
  поток. Ни PeerId, ни списка нод, ни идентификатора `/void/v1` в открытом виде
  нет ни в одном байте.

## Подключение обычного клиента VOID

Ничего не изменилось — для клиентов VOID нода по‑прежнему корректный
libp2p‑seed. В веб‑интерфейсе видна готовая строка для `void-bootstrap.txt`:

```
/ip4/<ВАШ_ПУБЛИЧНЫЙ_IP>/tcp/4001/p2p/<PEER_ID>
```

## Безопасность

- `bootstrap_peer.key` — статический ключ. Его утечка позволяет выдать себя за
  вашу ноду в seed‑обмене. Делайте резервные копии и храните в секрете.
- Веб‑интерфейс по умолчанию на `127.0.0.1` — **не открывайте его в интернет**
  без HTTP‑auth + TLS. Если нужно удалённое управление — ставьте перед ним
  Caddy/nginx с basic‑auth и валидным сертификатом.
- На роутере должен быть проброшен только `LISTEN_PORT` (TCP+UDP) и
  `SEED_PORT` (TCP). Всё остальное оставьте закрытым.
